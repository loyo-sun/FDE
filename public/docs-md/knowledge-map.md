# FDE 知识地图

状态：基础指南

全局大纲、学习路线与内容建设进度。

## 定位与使用方式

FDE 在这里指 **Forward Deployed Engineer（前沿部署工程师）**：深入客户真实工作流，识别高价值问题，编写和集成软件，验证业务效果，并把共性经验反馈给产品。它需要软件工程能力，也需要业务判断与客户协作能力。

本知识库按完成客户项目所需的能力组织。现有基础指南和新增大纲共同构成学习框架；大纲表示计划建设的主题，不代表已经提供完整教程。

## 三条学习路线

### 新人入门

[岗位认知](/docs/role-and-competency/) → [工程基础](/docs/engineering-foundations/) → [客户问题定义](/docs/business-discovery/) → [交付生命周期](/docs/delivery-lifecycle/)。

目标产出：解释 FDE 职责，运行一个最小服务，并写出一页问题定义。

### 项目实战

[成功指标](/docs/success-metrics/) → [方案架构](/docs/solution-architecture/) → [AI 应用交付](/docs/ai-delivery/) → [评测与验收](/docs/ai-evaluation-and-acceptance/) → [运维移交](/docs/acceptance-and-handover/)。

目标产出：形成有业务基线、实现、测试和移交证据的项目包。

[Agent 工作流](/docs/agent-workflows/) → [可观测性](/docs/observability/) → [威胁建模](/docs/ai-threat-modeling/) → [产品反馈](/docs/product-feedback/) → [方案复用](/docs/reusable-solutions/)。

目标产出：让系统在复杂场景下可控运行，并提炼可跨客户复用的能力。

- [价值假设与成功指标](/docs/success-metrics/) · 待完善大纲：把业务目标转成可测量的基线、目标和验收证据。

## 分阶段完善计划

1. **第一阶段：入门与问题定义。** 优先完善工程基础、客户访谈、场景筛选和成功指标，建立一个贯穿示例。
2. **第二阶段：工程与端到端项目。** 围绕该示例补齐架构、接口、数据管道、工作流界面和自动测试。
3. **第三阶段：AI 与生产可靠性。** 增补 Agent、评测数据、故障案例、权限测试和上线回退证据。
4. **第四阶段：复用与团队协作。** 沉淀产品反馈、参考方案、模板和经过评审的真实案例。

## 内容状态与质量标准

- **待完善大纲**：只有学习目标、计划章节和预期交付物，暂不能据此执行生产操作。
- **基础指南**：提供概念、方法或检查要点；不等于经过实战验证的操作手册。
- **操作手册**：补齐适用版本、前置条件、步骤、验证、回退和风险，并经过审核后才能标记。

公开内容只使用合成数据或已脱敏资料。内容更新、状态变更和审核记录通过 GitHub 追踪。
