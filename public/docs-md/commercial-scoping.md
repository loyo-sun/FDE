# 立项与交付经济性

状态：基础指南

在承诺交付前明确价值假设、总投入、责任与停止条件。

## 何时需要这项判断

客户愿意试用不等于项目值得持续投入。FDE 应在立项前把业务收益、工程实现、接入等待和长期运行放在同一张表中，说明谁承担费用、谁批准范围、什么证据支持继续。本文讨论项目投入判断，不提供价格或回报保证。

## 从价值假设到投入边界

先记录任务量、采用人数、任务频率、失败代价与现有替代。收益只能使用可验证的变化；节约时间能否释放成实际价值，由业务负责人确认。工程估算应包含调研、集成、测试、数据清理、部署、培训、运维与退出，不能只统计模型费用。

| 投入项 | 估算依据 | 容易遗漏的负担 |
| --- | --- | --- |
| 初次实现 | 任务切片、系统数量、接口成熟度 | 环境准入和历史数据清理 |
| 持续运行 | 请求量、模型和基础设施使用 | 审核、值班和升级回归 |
| 协作与采用 | 用户培训、流程调整 | 专家复核与额外审批 |
| 退出与迁移 | 数据量、依赖和合同边界 | 撤权、备份处置和替代系统 |

## 形成可评审的立项约定

写明目标、首期纳入与排除、数据授权、双方负责人、投入上限、阶段证据及停止条件。FDE 负责提供工程依据；商业承诺和预算批准由有权负责人决定。接口未授权时，可以验证合成原型，但不能宣布真实接入可行。

## 贯穿案例中的判断

售后工单助手只做授权检索和人工复核草稿。先比较整理时间、专家审核时间与错误返工，再估计每月实际可释放的投入。若整理快了但专家工作翻倍，或只有极少任务能用，应调整范围，而不是直接扩大模型预算。

用保守、中性和乐观三种情形改变任务量、采用率、审核负担与运行单价；说明结论是否对某个假设高度敏感。这里不预设收益数字，必须先获取基线。

## 阶段退出与扩展决定

数据用途无法确认、关键权限不能隔离、任务收益抵消不了新增负担，都是合理停止条件。扩大设备系列、增加自动动作或跨系统写入，要重新估算测试、运行与风险成本。停止实验也应留下证据，避免同样的假设再次消耗团队。

## 练习与完成标准

提交一页价值假设、投入分解、三种情形和停止条件。每项关键数字注明样本、来源或待验证状态，由业务和工程负责人分别复核。[成功指标](/docs/success-metrics/)提供测量方法，[上线价值复核](/docs/value-realization/)负责检验这些假设是否兑现。
