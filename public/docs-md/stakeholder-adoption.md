# 干系人协作与用户采用

状态：基础指南

推动业务负责人、使用者和技术团队共同验收价值。

## 采用从协作设计开始

系统上线后无人使用，通常不能只归因于培训不足。可能是任务不适配、复核太贵、责任不清或既有激励冲突。先识别谁从系统获益、谁付出额外劳动、谁能决定改变流程。

## 干系人责任表

| 角色 | 需要决定或承担 | 应参与的证据 |
| --- | --- | --- |
| 业务负责人 | 目标、范围、价值验收 | 基线与试点报告 |
| 一线工程师 | 使用与反馈 | 任务观察、修改原因 |
| 专家审核人 | 草稿质量与高风险接管 | 评分规则与失败样本 |
| IT / 安全 | 身份、环境与数据边界 | 架构与安全验证 |
| 运维负责人 | 告警、恢复与升级 | 演练和移交记录 |

每个关键决定应有一位最终负责的人，不把“共同负责”写成无人负责。

## 试点设计

从小范围自愿用户开始，覆盖不同熟练度和任务难度；说明系统用途、限制、反馈入口和人工替代。试点用户不能只选最支持项目的专家，否则采用结果容易偏乐观。

培训围绕实际任务：如何核对版本、查看引用、修订草稿、发现错误、转人工。让学员完成任务并解释错误处理，观看演示不等于掌握。

## 采用指标与反馈

记录有资格使用的人数、实际开始任务人数、成功完成人数、重复使用和放弃原因。登录次数和页面访问量只能说明触达；需结合任务结果、用户耗时和审核负担。

工单助手若草稿采用率高但审核时间翻倍，应调查是否只是把劳动移给专家。把反馈分为缺功能、质量错误、流程不适配和使用障碍，再安排改进。

## 练习与完成标准

提交责任表、试点招募标准、一次任务式培训和反馈分类表。试点结束后给出继续、调整或停止建议，并说明样本限制。下一步把共性问题转成[产品反馈](/docs/product-feedback/)。
