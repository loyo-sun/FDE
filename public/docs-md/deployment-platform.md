## 从运行边界设计平台

部署平台的任务是让应用可重复发布、可观测运行并能在约定范围恢复。先确认客户可提供什么环境、网络、身份和运维能力，再选择虚拟机、容器、托管平台或客户本地环境。平台复杂度应与团队接手能力相匹配。

## 最小环境清单

| 边界 | 需要确认 | 证据 |
| --- | --- | --- |
| 网络 | 入口、出口、代理、DNS 与 TLS | 允许依赖与连通性结果 |
| 身份 | 人员、服务与部署账号 | 最小权限和轮换责任 |
| 配置 | 环境差异、密钥和功能开关 | 配置样例与校验机制 |
| 制品 | 来源、版本、依赖和完整性 | 锁文件、构建记录与校验 |
| 持久化 | 数据、文档、任务和审计 | 备份、恢复与保留说明 |
| 运行 | 配额、监控、告警与值班 | 服务目标与接手人 |

## 开发、测试与生产的关系

各环境使用独立身份与明确数据范围；测试环境尽量复现真实约束，但不复制未授权生产资料。环境相似性需要列出差异，避免把本机桩服务通过当作客户网络联调完成。

对配置进行类型和范围校验，缺少必要密钥或依赖时拒绝危险启动。密钥不进入镜像、代码、构建日志或公开操作文档。运行配置与应用制品分别版本化。

## 发布与恢复

制品应能对应源代码与构建证据，避免上线时临时改服务器。先验证健康，再验证真实业务和权限；模型不可用时仍可进入人工流程。应用回退不等于数据恢复，不可逆迁移必须单独安排。

工单助手部署需要同时确认知识存储、检索、模型出口、后台任务和引用查看链路。仅浏览器首页打开，不能证明后台索引可更新或运维可恢复。

## 平台迁移与退出

迁移前清点外部依赖、数据量、作业与配置；先演练复制、对账和恢复，再明确切换窗口、停止写入或双写风险。切换后检查权限、历史任务与引用；旧平台在责任终止前按计划撤权和清理，不长期遗留无人维护的副本。

## 练习与完成标准

提交环境拓扑、允许依赖、配置样例、制品来源和一次失败恢复说明。让接手方复现发布与恢复，指出尚未验证的客户差异。阅读[上线准备](/docs/site-delivery-sop/)与[系统退出](/docs/solution-exit/)。
