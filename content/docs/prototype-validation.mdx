## 原型服务于决策

原型不是缩小版成品，而是验证某个高风险假设的实验。先写“测试结果将改变哪个决定”，再选最便宜的验证方式。界面草图验证任务理解，数据探查验证可用性，技术切片验证集成约束；它们不能互相代替。

## 实验卡片

| 字段 | 合成案例示例 |
| --- | --- |
| 假设 | 使用正确版本资料可减少回复整理时间 |
| 对照 | 工程师使用现有搜索完成相近任务 |
| 处理 | 助手检索并生成带引用草稿 |
| 数据 | 合成工单与授权测试资料，按难度分层 |
| 测量 | 总耗时、错误、复核时间、拒答与成本 |
| 停止 | 出现越权内容，或审核负担抵消节省 |
| 决策 | 继续、缩小范围、修改方案或停止 |

## 用最小技术切片验证集成

先连通身份、单条工单、单份资料和单条草稿。这个切片应包含真实鉴权与错误路径，而不是只展示静态成功截图。若数据无法获取，优先验证接入可行性；若模型引用不可靠，优先验证证据与评测。

## 时间盒与产出

为实验设置短时间盒，例如三天，这是组织工作的示例而非行业标准。结束时交付假设、配置、样本、结果、限制和决定。失败实验仍有价值，但需要明确排除了什么，不能无限延长直到出现想要的结论。

## 从原型走向生产的缺口

| 原型可简化 | 上线前必须补齐 |
| --- | --- |
| 少量合成资料 | 数据授权、更新与删除流程 |
| 单用户手工运行 | 身份隔离、并发与配额 |
| 临时日志 | 脱敏、审计与告警 |
| 手动恢复 | 可验证回退与值班责任 |

## 练习与完成标准

用[实验记录模板](/templates/experiment-record.md)写一个可以失败的实验；让评审人仅凭记录判断是否继续。只展示顺利样例、没有对照或没有停止条件的原型尚不足以支持上线决定。
